clear-writing の工程の詳細。全体像は `SKILL.md` にある。

## 推敲

**推敲は読み返しではなく、見るものを一つに絞った通しを重ねて、文章から離れた操作で欠陥を検出する
作業。** 工程7 まで通った全文にかけ、終わってから「出力」へ進む。工程ごとの条件はその工程の中
だけを見るので、工程を跨がないと見えないものはここでしか出ない。落ちたら、原因になっている工程
まで戻る。

書き手はその文章の意味を既に知っているので、読み返すと足りない語を頭が補い、欠陥が欠陥として
残らない。逃げ道は二つ。条件を文章から離れた操作に置き換えることと、自分を読者の位置へ移すこと。

**読者の位置へ移す。** 時間を置くと記憶が薄れる。急ぎなら別の作業を挟んでから戻る。媒体を変えると
見慣れた形が崩れて読み飛ばしが減る（紙に出す、幅とフォントを変える、送る場所に貼って見る）。音読
すると文の欠陥が音で出る。息が続かない文は長すぎ、つっかえる箇所は係り受けが壊れている。機械に
読ませると補完が効かない（macOS なら `say -f draft.md -r 250`）。これは筆者が自分の文章にかける
仕掛けで、下書きを作った直後に時間は置けない。置けないときは三つのパスの操作だけで代替する。

**別のエージェントを立てるのは、段落が五つ以上あるときとする。** それ未満なら全文を一度に見られる
ので、補完が起きても筆者が本文ごと確かめられる。立てる場合、構造のパスと事実のパスのエージェントは
入力が別なので、同じ応答でまとめて起動してよい。Agent tool が使えない環境では自分で通し、補完を
切れていないことを確認事項に書く。

**見るものを一つに絞った通しを三度重ねる。** 一度の読みで構造も文も誤字も直そうとすると、誤字を
見つけた瞬間に構造を見る目が切れる。上流から順に、一つずつ。

### 構造のパス

中身を読まず骨格だけを見る。中核は**逆アウトライン**で、全文が揃ってからしか実行できない。

**逆アウトラインは別のエージェントに作らせる。** 自分で作ると、段落を読んだ時点で書いたときの意図が
補われ、本文にある一行ではなく書いたつもりの一行が出る。本文だけを渡し、前提・アウトライン・素材は
渡さない。渡せばそれに沿った一行が返り、突き合わせる意味がなくなる。

本文を `tmp/` の別ファイルへ切り出してから頼む。工程ファイルには前提が入っているので、そのまま
渡さない。

```
次のファイルの文章を読み、段落ごとに、その段落が何を主張しているかを一行で書き出してください。
要約ではなく、この段落は何をしているかを書いてください。
一行で書けない段落があれば、段落番号と理由（主張が混ざっている／主張がない）を挙げてください。
ファイル: tmp/<本文>.md
```

返ってきた一行を並べて突き合わせる。

1. **工程5 の各節の一文と突き合わせる。** 一致しない箇所が、意図と実際のずれ
2. **一行で書けないと報告された段落を直す。** 主張が混ざっているか、主張がない。分割するか削る
3. 同じ一行が二度あれば重複で、片方は削れる。並びが飛んでいれば順序が読み手の理解順になっていない。
   一行と一行の間に飛躍があれば、そこに段落が一つ足りない

続けて、工程を跨がないと見えない三つを見る。

- **工程3 で落とすと決めた素材が本文に残っていないか。** 残っていないのに長いなら、原因は構造にある
- **行動が要るなら、誰が・何を・いつまでに、を指差せるか。** 要らないなら、要らないと書いてあるか
- **読者の既存の立場と衝突する主張があるなら、合意できる事実から始まっているか**

直す単位は節で、文ではない。

### 文のパス

句点で切って一文ずつ見る。**工程7 の出口条件をそのままもう一度かける。** 書いたときとは別の通しに
なるので、同じ条件でも落ちる箇所が変わる。

運用で足すことが一つ。**検索で見つかるものを目視で探さない。**「ない」「ません」、中身のない語、
指示語は検索する。

### 事実のパス

意味を読まず表面だけを見る。冒頭の「素材にない事実・数値・主張を作らない」は、ここで初めて検査
される。書いている最中にやると意味を読んでしまうので、独立した通しにする。

- 数値・日付・曜日・固有名詞・リンク先の実在を確かめる
- 日付は暗算しない。`python3` で出す。本文の日付を検証したら、例示に使った日付も同じ方法で検証する
- 末尾から先頭へ逆順に読むと内容の流れに乗らないので、誤字が見つかりやすい

#### 素材との対応表

**本文の主張が素材のどこから来たかの対応表を、別のエージェントに作らせる。** 素材にない主張は、
体裁が整っているほど本文を読んでも見つからない。筆者は最初の読者なので、全文を渡せば同じように
素通りする（性質3）。確かめる対象を、出どころを指せなかった行だけに絞って渡す。

素材と本文だけを渡す。前提・中心文・工程の記録は渡さない。自分で作ると、書いたときの根拠が
思い出されて、素材にない主張にも出どころが付く。素材がファイルになっていなければ、工程3 の
「既知」と「知るべき未知」を依頼文に貼る。

```
次の二つのファイルを読み、本文の主張それぞれについて、素材のどこから来たかの表を作ってください。
列は「本文の主張（一文）」「素材の出どころ（該当箇所の引用）」「判定」。
判定は次の三つから選んでください。
  素材どおり／素材より強い（断定が強い・範囲が広い・条件が落ちている）／素材にない
出どころを引用で指せない主張は「素材にない」にしてください。
素材: tmp/<素材>.md
本文: tmp/<本文>.md
```

全行を `tmp/` の工程ファイルへ追記し、**「素材より強い」と「素材にない」の行だけを出力の確認事項に
載せる。** 全行を載せると、確認する側が本文と同じ量の問題に当たり、斜め読みが戻ってくる。

「素材にない」行の行き先は、削る・素材を足す・確認事項に上げるの三つしかない。判断を保留したまま
本文へ残さない。

### 削る量を先に決める

制約がないと手が動かないので、削る量を数で先に決めてから入る（一割など。実測ではなく、手を動かす
ための制約）。判定は一つで、**その文を消して読者が失うものを言えるか**。言えなければ消す。最初の
候補は、検討の経緯、前置き、読者が既に推論できる自明な文、同じ主張の二つ目以降の根拠。
**削るのは節からで、文からではない。**

### 終了条件

推敲は無限に続けられるので、終わりを決めてから始める。

1. 三つのパスをそれぞれ一度通したか
2. 読む量の予算に収まっているか
3. 各パスで直す箇所が出なくなったか
4. 対応表の「素材にない」「素材より強い」行が、削られたか確認事項に載ったか

**同じパスで二度続けて同じ種類の指摘が出たら、直し方ではなく上流の工程に原因がある。**
