# 工程6〜7: 節・文

clear-writing の工程の詳細。全体像は `SKILL.md` にある。

---

## 工程6: 節

**アウトラインの節を一つずつ埋める。** 守ることは三つ。

- 一つの節に一つのトピックだけを置く
- 段落の最初の文を読めば、その段落が何の話か分かるようにする（性質1）
- 段落の先頭だけを繋げて読んでも筋が通るようにする（性質3）

### 分量は情報量に見合わせる

判定の基準は長さではなく、**その分量に見合う情報が入っているか**。

**自明な文を書かない。** 読者がその時点で既に推論できることを書いても、情報は増えず分量だけ増える。

```
悪い例: 使いたい人は使えます。（入れ方を書いてあれば自明）
悪い例: ご不明な点があればお問い合わせください。（連絡先を知っている相手には自明）
```

**例は具体的な文面で出す。** 抽象的な言い換えは例として働かない。

```
悪い例: してほしいことが書いていない、期限が「来週」のまま、背景と依頼が一文に混ざっている
良い例: 「例の件、確認お願いします」→「決済画面のエラー調査をお願いします。
        明日の定例までに原因の見当がつくと助かります」
```

具体的に書けないなら例そのものを省く。抽象的な例は無いより悪い。

**一つの主張に一つの根拠。** 読者は一つ目で納得するかしないかが決まっていて、二つ目以降は
分量だけを増やす。

### 工程6 の出口

**アウトプット**: アウトラインの各節が埋まった本文。

**次へ進む条件**

1. 各節が工程5 で書いた一文と一致するか。ずれていたら、節を直すか工程5 へ戻る。一文にまとまらない節はトピックが二つある
2. 各文を一つずつ消してみて、消しても読者が失うものを言えない文が残っていないか
3. 例が鉤括弧の中の文面になっているか。分類の列挙で済ませていないか

## 工程7: 文

**節が埋まったら、文を一つずつ直す。** 日本語で誤読が起きるのはほぼ**一文への意図の詰め込み**と
**係り受けの取り違え**で、どちらも性質2 の現れ。**まず一文が担う意図を一つに割り、次に語順を直す。**
そのうえで否定形、書き落とし、中身のない語を見る。

### 一文に一つの意図だけ書く

一文が担う意図は一つにする。工程4 の文意が文章全体の意図で、各文はその構成要素として一つの意図を
担う。意図の実体は目的の種類で変わり、依頼なら頼みたいこと、説明なら主張、記録なら事実にあたる。

```
悪い例: 先週リリースした決済画面でエラーが出ていて、原因は API 側らしいので、
        調査をお願いしたいのですが、明日の定例までに分かると助かります。
良い例: 決済画面のエラー調査をお願いします。明日の定例までに原因の見当がつくと助かります。
        先週のリリース後から発生していて、API 側が原因と見ています。
```

**短くすること自体を目的にしない。** 文を割るときに接続の語（だから、ただし、そのため）まで落とすと
論理関係が消え、理解は下がる。割ったら接続を明示して繋ぎ直す。前提知識が低い読者層ほど短くする。

### 語順: 既知が先、新しいことが後ろ

```
悪い例: 新しい承認フローを、先週の障害の再発防止として導入します。
良い例: 先週の障害の再発防止として、新しい承認フローを導入します。
```

読者は文の前半を手がかりに記憶の該当箇所を探し、そこへ後半を接続する（性質1）。この順を崩すと、
同じ内容でも読む時間が伸びる。文末は最も注目される位置なので、持ち帰ってほしい内容を文末に置く。
主語と述語は離しすぎない。

**修飾は長いものを先、短いものを後に置き、読点はその境界に打つ。** 既知と新の順では係り先が
決まらないので、別に要る（「至急先週の障害で影響を受けた顧客のリストを」→「先週の障害で影響を
受けた顧客のリストを、至急」）。**主名詞の前に修飾節を二つ以上積まない。** 既知か新かによらず、
名詞に到達するまで保持させることになる。積むなら文を分けて後ろへ出す。

### 否定形は肯定形に書き換える

```
悪い例: 金曜までに返信がない場合は、進めないでください。
良い例: 金曜までに返信があれば進めてください。返信がなければ止めてください。
```

否定を理解するには、否定される肯定命題を組み立ててから反転する必要がある（性質2）。二重否定は
さらに悪い。

### 書いていないことは伝わらない

- **伝えたい態度は文として書き出す**。含みや言い回しでは伝わらない（「急かす意図はありません」
  「これは確認で、やり直しの依頼ではありません」）
- **事実と意見を書き分ける**。観測した事実、他者の主張、自分の推測を文末で区別する
  （「〜だった」「〜と聞いた」「〜だと思う」）。確認していないことを確認したように書かない
- **誰がするのかを書く**。受動態は行為者を消す（「調査が行われる」→「誰が調査する」）

### 中身のない語を使わない

- **予告**: 「重要なのは〜です」「〜について共有させていただきます」——主張をそのまま書く
- **空虚な形容**: 「抜本的」「包括的」「根本的」——何がどうなのかを書く
- **無生物主語の擬人化**: 「このデータが示しているのは」→「このデータから分かるのは」
- **英語慣用句の直訳**: 「開かれた問い」→「まだ答えが出ていない」、「〜が効く」→ 効果の中身を書く

### 工程7 の出口

**アウトプット**: そのまま渡せる状態の全文。

**次へ進む条件**

1. 句点で切って、各文が何をしたいかを一語で言えるか
2. 各文の文頭が、前の文までに出た語から始まっているか
3. 主名詞の前の修飾節を数えて、二つ以上ないか
4. 「ない」「ません」と、中身のない語（「重要なのは」「抜本的」「させていただきます」）を検索したか
5. 推測を事実として書いた箇所がないか。文末で区別したか
