# 工程1〜4: 読者・目的・素材・文意

clear-writing の工程の詳細。全体像は `SKILL.md` にある。

---

## 工程1: 読者

**読者は、その文章が誰の判断や作業を変えるかで決める。** 筆者の所属チームで決めない。
「チームに共有」「みんなに周知」のような曖昧な指定は、そのまま受け取ると筆者の隣の席までしか
届かない。技術的な決定でも、それが施策の設計や運用のやり方を変えるなら、企画する側も読者に入る。

**指定されていなければ、素材から推定する。聞かない。** 推定して書いたものは、外れていれば
人間が下書きを見ながら一秒で訂正できる。聞くと必ず一往復かかるが、推定は当たれば往復ゼロで、
外れたときだけ作り直しになる。作り直しは人間の往復より安い。

読者がどうしても決まらないときは、**最も条件の厳しい層**（前提知識が低く、読む量の予算が
小さい）に向けて書く。

決まったら、**役割から推定できるものは推定してよい**。前提知識・関心・読む量の予算・読み方の好みは、
役割（PdM・エンジニア・全社・社外）からの一般論で足りる。社外の読者には、社内の固有名詞と略語が
通じない前提で書く。推定した内容は出力の「この下書きの前提」に添えて、外れていれば訂正してもらう。

**読む量の予算だけは数で書く。** その読者がこの話題に割く分量を、媒体と関心から見積もる
（「Slack で二スクロール」「画面一つ」「八〇〇字」）。数にしないと工程5 で節の数を逆算できず、
総量が予算内かも確かめられない。

読者は個人とは限らない。チーム・部門・全社・不特定多数も読者層であり、**個人は「一人しかいない
読者層」として同じに扱う**。集団は各項目が一点に決まらないので、**前提知識と読む量の予算は最も
条件の厳しい層に合わせる**（平均に合わせると、下限の人が落ちたことに誰も気づかない）。
**立場が割れている論点は「割れている」と書き、一つに丸めない**。

読者が複数の層にまたがるときは、質問せず構造で解く。層ごとに区画を分け、どこまで読めばよいかを
本文に書く。外部の個人はコードネームで扱い、氏名・連絡先を書かない。

### 工程1 の出口

**アウトプット**: 読者の一行。役割・前提知識・関心・読む量の予算。

**次へ進む条件**

1. 読者を一行で書き出せるか。「チームに」のような指定なら、誰の判断や作業が変わるかを名指しに開いたか
2. 役割から推定した項目を、その一行に入れたか
3. 読む量の予算が数になっているか。集団なら最も条件の厳しい層の数か

## 工程2: 目的

**読み終えた読者がどうなっているかを一文で書く。** これが以降の全判断の基準になる。

```
悪い例: 新しい skill について説明する
良い例: 読み終えた読者が、この skill を自分で試すか見送るかを判断できている
```

| 種類 | 読み終えた読者の状態 | 必要な要素 |
|---|---|---|
| **承認を求める**（決裁依頼・稟議・相談） | 承認するか差し戻すかを決められる | 決めてほしいこと・期限・選択肢と推奨・影響とコスト |
| **実作業を求める**（依頼・アサイン） | 何をどうすればよいか分かっている | してほしいこと・期限・前提と手順・完了条件・断る場合の選択肢 |
| **判断を共有する**（決定・報告） | 何が決まったか・なぜかを説明できる | 決めたこと・理由・却下案とその理由・影響範囲・決定者と委任度・異論の期限 |
| **異議を伝える**（指摘・反対・断り） | 何が問題で、次にどうすればよいか分かっている | 何に反対か・その根拠・代案か条件・相手が取れる選択肢 |
| **理解させる**（説明・解説・記事） | 対象を自分の言葉で説明できる | 中心となる考え・支える根拠・具体例・限界 |
| **記録する**（議事・ログ・手順） | 後から探して同じ結論に到達できる | 事実・日付・決定と保留・参照先 |

委任度は「自分が決めた／チームの提案を自分が承認した／チームが決めた」。これが無いと読者は関与
できるのか判断できず、決まった話が後から蒸し返される。

**種類が決まった結果、その判断をするのが別の人だと分かったら、工程1 へ戻る。** 承認を求める文章の
読者は決裁できる人で、実作業を求める文章の読者は手を動かす人である。読者と目的は互いを
決め合うので、ここだけは後ろから前への戻りが予定されている。

### 工程2 の出口

**アウトプット**: 目的の一文と、五つの種類のうちどれか。

**次へ進む条件**

1. 工程1 の読者を主語にして、「読み終えた読者がどうなっているか」の形で一文になっているか
2. 種類を一つ選び、その行の「必要な要素」を一つずつ素材から拾えるか。拾えないものを確認事項へ回したか
3. 判断を共有するなら、決定者と委任度が素材から取れているか

## 工程3: 素材

**素材は、探してから三つに分ける。** 順序を逆にすると、既に決まっていることを知らないまま
「知らなくてよい」に落とす。

**1. この話題について過去に何が決まっているかを探す。** 推定してはいけない。役割からの一般論では
出てこず、外すと決まった話を蒸し返す文章になる。**どこを探すかは指定しない。** 手元の記録、議事、
課題管理、文書置き場、チャットの履歴から、その環境で使える手段を選ぶ。探して出てこなければ、
決まっていないものとして進む。

見つかった決定は、読者が既に共有している前提として扱い、そこへ接続する形で書く。衝突する主張を
書くなら、合意できる事実から始める。読者が既に持っている理解に接続できない主張は、読まれても
受け取られない（性質1）。

**2. 素材を三つに分ける。** 基準は「読者の判断を変えるか」。

- **既知**: 読者が既に知っている。説明せず、文脈の足がかりとして使う
- **知るべき未知**: 判断を変える。本文に置く
- **知らなくてよい**: 判断を変えない。**落とす**

目的の種類を基準にしない。目的を一つに絞ると副次的な目的が要求する要素まで落ちる。説明が目的でも、
読者が導入の可否を決める立場なら工数は判断を変えるので残す。

```
落とす: 「調べたところ、A 案と B 案が見つかりました。A 案は〇〇のため見送り、B 案を採りました」
残す:  「B 案で進めます」（判断の共有が目的なら A 案の却下理由まで残す）

落とす: 「Bransford & Johnson (1972) の実験では、題を読む前に与えた群だけ理解が向上しました」
残す:  「最初の一文に、何をしてほしいかを書いてください」
```

出典（誰の研究か・どの文献か）は、たいてい判断を変えないので落とす。残すのは、読者が自分で
検証する立場にいるときだけ。

橋渡しを厚くすると前提知識の低い読者は助かるが、高い読者ではかえって理解が下がる。
**既定は「迷ったら明示する」**とし、高いと分かっている層でだけ減らす。

### 工程3 の出口

**アウトプット**: 素材の三分類。既知・知るべき未知・知らなくてよい。

**次へ進む条件**

1. 探した先を挙げられるか。見つからなければ、決まっていないと書けるか
2. **落とすものを名指しできるか**
3. 既知に入れたものが、探して確かめた事実か。推定で既知にしていないか

## 工程4: 文意

**この文章が言いたいことを一文で書く。** 書けないなら、まだ書き始める段階にない。

この一文を「中心文」と呼ぶ。支える主張は**三つまで**。性質2 により、読者が同時に保持できる筋は
限られる。四つ以上出てきたら、そのいくつかは中心文の言い換えか、別の文章にすべき内容である。

```
中心文: 文章の伝達の失敗は、筆者に見えにくいだけで原因はほぼ決まっている
支える主張1: 相手に何をしてほしいか書いていない
支える主張2: 期限が相対表現のまま残っている
支える主張3: 背景と依頼が一文に混ざっている
落とした: 伝わらない文章には共通の型がある（中心文の言い換え）
```

### 工程4 の出口

**アウトプット**: 中心文の一文と、支える主張の箇条書き（三つまで）。

**次へ進む条件**

1. 中心文を一文で言えるか
2. 目的の一文と中心文を並べて、中心文が目的を満たすか
3. 支える主張を一つずつ消してみて、消すと中心文が痩せるか。痩せないものは言い換え
