# pr-develop — 開発セッション開始

Issueに記録した「意図」を現在のセッションに注入するスキル。「やること」と「やらないこと」を明示することでスコープ外の実装への誘惑を抑止する。

プロジェクトの CLAUDE.md が base ブランチ・ブランチ名・作業場所（worktree など）を決めていれば、それに従う。

## 引数

`$ARGUMENTS` からIssue番号を読み取る（`#42` または `42` の形式）。
番号がなければ `gh issue list --assignee @me --state open` を実行し、ユーザーに選んでもらう。

## Step 1: スコープを要約して表示

`gh issue view <番号>` で Issue を読み、以下の形式でセッションのスコープを宣言する。この表示がセッション中の判断の基準になるので、「やらないこと」を省かない:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  開発セッション開始: Issue #<番号>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

課題:
  <1行>

解決の意図:
  <1行>

やること:
  - <項目>

やらないこと（この実装では触れない）:
  - <項目>

完了条件:
  - <条件>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## Step 2: 作業場所を用意する

base ブランチ（CLAUDE.md が決めるもの、なければリポジトリの既定ブランチ）にいる場合だけ、作業用のブランチを用意する。すでに作業用のブランチにいれば、その旨を伝えてスキップする。

- **作業場所:** CLAUDE.md が worktree や専用の skill を決めていれば、それで用意する
- **ブランチ名:** CLAUDE.md の規則に従う。規則がなければ `git branch -r` で既存のブランチ名を見て形式を合わせ、Issue 番号を含める。形式を決め打ちすると、リポジトリの慣習とずれる
- **起点:** base ブランチの最新から切る

## Step 3: セッション開始を宣言

> スコープを確認しました。実装を開始してください。
>
> - コミットは意図単位で。準備ができたら `/commit` を使ってください
> - スコープ外の作業が必要になったら実装を止め、新しいIssueを `/pr-plan` で作成してください
> - 実装が終わったら `/pr-process` で続きを進められます（セルフレビュー → PR 作成）
